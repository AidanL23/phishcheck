# How the queue survives crashes

When a worker reads a job through a Redis consumer group, Redis hands the entry to exactly one worker and records it in the group's Pending Entries List (PEL), which tracks who owns each in-flight job and how long it has been idle. The worker removes the job from the PEL with XACK only after it has finished and saved the result; the entry stays in the stream, which is why the stream is also trimmed with a maximum length. If a worker crashes before acking, the job stays in the PEL under the dead worker's name and Redis never re-delivers it on its own, so without recovery the job would sit "in progress" forever. PhishCheck fixes this with a reclaim loop that runs every 30 seconds and uses XAUTOCLAIM to take over any entry idle for more than 60 seconds, so a crashed worker's job is picked up by a healthy worker within about 90 seconds, and a job that fails three times is moved to a dead-letter stream instead of retrying forever.
